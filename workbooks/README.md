## Update Protocol

When a publication is confirmed as published:

1. Verify the publication's title, publication ID, date, public link, and approved story preview against the canonical publication record or user-confirmed information.
2. Add or update the corresponding entry in each of the four workbooks, keeping each workbook's scope distinct.
3. Preserve existing approved content and historical entries. Make additive changes unless a revision is explicitly requested.
4. Keep **LOCKED**, **CURRENT / WORKING**, and **DRAFT / PROPOSAL** states distinct. Do not promote a proposal to a locked decision without explicit approval.
5. Do not infer an article sequence number from a Publication ID. They are different identifiers.
6. Verify the changed files and provide the resulting GitHub commit link(s).

## Record Integrity

- Use **SARGEN™** consistently as the brand name.
- Preserve established terminology and locked decisions.
- Do not duplicate the canonical Publication Register as a competing source of truth.
- If source material conflicts or an important detail is missing, flag the issue instead of silently resolving it.
- The GitHub repository is the durable record; separate ChatGPT conversations may be used for drafting and discussion but are not themselves repository updates.
